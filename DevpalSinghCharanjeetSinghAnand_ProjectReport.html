Abstract

StreamSafe is a dual-component cybersecurity toolkit developed for the IBM SkillsBuild Cyber Security BootCamp 2026. It addresses a critical and largely overlooked problem in digital forensics: the silent loss of NTFS Alternate Data Streams (ADS) during standard archiving operations.

The project comprises two complementary tools. The first is a full-featured desktop application built with Tauri v2 (Rust + React), providing a modern GUI for forensic-grade archiving with SHA-256 verified stream preservation across five archive formats. The second is a standalone Python GUI utility (app.py) that enables forensic investigators to create, list, read and delete ADS streams on any file, folder or ZIP archive using direct Windows kernel API calls via ctypes — with no third-party dependencies.

Together, these tools fill a genuine gap in open-source digital forensics tooling, providing investigators with reliable, verifiable ADS handling that tools like 7-Zip, WinRAR and even cloud storage silently fail to provide.

Introduction & Problem Statement

Digital forensics investigations frequently involve the acquisition, preservation and analysis of file system artefacts. A major but underappreciated challenge arises from the NTFS file system feature known as Alternate Data Streams — hidden data channels attached to ordinary files and folders that mainstream archivers universally discard without warning.

The forensic impact is significant: critical investigative metadata, Zone.Identifier origin markers, thumbnail caches, and attacker-planted payloads are all routinely stored in ADS. When an investigator copies evidence to a ZIP or 7Z archive, these streams vanish silently — potentially destroying evidence or missing concealed malware.

The Core Problem

  • 7-Zip, WinRAR, Windows built-in ZIP — all silently drop ADS with zero warning
  • Cloud storage (OneDrive, Google Drive) strips ADS on upload
  • FAT32 and exFAT drives cannot store ADS — streams lost on copy
  • No open-source tool provides ADS-aware archiving with integrity verification
  • Investigators have no reliable way to confirm stream preservation after archiving

The Solution

StreamSafe provides two tools that together solve this problem: a production-grade desktop archiver that preserves ADS inside standard archive formats with cryptographic verification, and a lightweight Python forensics utility for direct ADS inspection and manipulation during active investigations.

What are NTFS Alternate Data Streams?

NTFS (New Technology File System), used by all modern Windows installations, supports a feature called Alternate Data Streams. Every NTFS file technically has at least one stream — the default unnamed stream that contains the file's visible content. However, NTFS allows any number of additional named streams to be attached to the same file.

# A file on NTFS can look like this: document.txt ← the file you see in Explorer (default stream) document.txt:Zone.Identifier ← hidden ADS: marks file as downloaded from internet document.txt:thumbnail ← hidden ADS: thumbnail cache document.txt:secret_payload ← hidden ADS: could be attacker-planted malware

Forensic Significance of ADS

🌐
Zone.Identifier
Windows marks every downloaded file with its origin URL in this ADS. Critical evidence in malware investigations.
🦠
Malware Hiding
Attackers store executable payloads in ADS to evade detection. The file appears innocent; the ADS contains the threat.
🖼
Thumbnail Cache
Windows stores image thumbnails in ADS, providing evidence of files that have since been deleted.
📋
Application Metadata
Office apps, browsers and security tools all write metadata into ADS — timestamps, author info, scan results.

StreamSafe Desktop Application

The StreamSafe desktop application is the primary tool — a production-grade forensic archiver built with Tauri v2, providing a native Windows desktop experience through a Rust backend and React frontend.

User Interface

Dark Mode Interface
Light Mode Interface

Core Features

  • ADS-Aware Archiving — preserves all NTFS alternate data streams inside archives using a structured __ads__/ directory layout
  • 5 Archive Formats — ZIP, TAR+ZSTD, TAR+GZ, TAR+XZ, 7Z — all with full ADS support
  • SHA-256 Verification — every stream hashed before packing; verified after extraction and reported as PRESERVED / MISSING / MISMATCHED
  • Forensic Manifest — JSON manifest embedded in every archive containing file paths, stream names, sizes and hashes
  • Operation Log — timestamped plain-text log of every pack and extract operation
  • File Explorer — built-in drag-and-drop file browser for selecting targets
  • Stream Viewer — inspect all ADS on any selected file before archiving
  • Live Progress — real-time progress events streamed from Rust backend to frontend
  • Dark & Light Mode — full theme support
  • Single .exe — no installation, no runtime dependencies

Archive Structure (ADS Format Specification)

archive.zip ├── manifest.json ← forensic manifest with all hashes ├── operation.log ← timestamped operation log └── files/ ├── document.txt ← base file, byte-for-byte identical └── __ads__/document.txt/ ├── Zone.Identifier ← raw stream content, unmodified └── thumbnail ← each stream stored separately

Forensic Manifest Schema

{ "version": "1.0", "tool": "StreamSafe", "created_at": "2026-10-26T09:00:00Z", "files": [ { "path": "document.txt", "base_hash": "sha256:abc123...", "base_size": 1024, "streams": [ { "name": "Zone.Identifier", "hash": "sha256:def456...", "size": 26 } ] } ] }

Verification Engine

After extraction, StreamSafe runs a full verification pass against the manifest:

StatusMeaningAction Required
✅ PRESERVEDSHA-256 matches manifest exactlyNone — evidence intact
❌ MISSINGStream in manifest but not found after extractionInvestigate — possible corruption or tampering
⚠ MISMATCHEDStream found but hash does not match manifestCritical — evidence may be tampered

Python ADS Tool (app.py)

The Python ADS Tool is a standalone forensic utility built entirely on Python's standard library. It provides a graphical interface for direct ADS manipulation — aimed at investigators who need quick, lightweight ADS inspection without launching the full desktop application.

Key Design Decisions

  • Zero dependencies — uses only Python stdlib (tkinter, ctypes, hashlib, threading)
  • Direct kernel calls — calls Windows API via ctypes, identical to how the Rust backend works
  • Non-blocking — all operations run on background threads; UI never freezes
  • SHA-256 on write — every written stream is immediately hashed and displayed in the console
  • Works on files, folders and ZIPs — any NTFS target is supported

Core ADS Functions in app.py

# Write an ADS stream with SHA-256 verification def ads_write(target_path, stream_name, content): stream_path = f"{target_path}:{stream_name}" handle = kernel32.CreateFileW(stream_path, GENERIC_WRITE, ...) kernel32.WriteFile(handle, buf, len(content), ...) sha256 = hashlib.sha256(content).hexdigest() return {"bytes_written": written.value, "sha256": sha256} # List all ADS streams on a path def ads_list(target_path): data = WIN32_FIND_STREAM_DATA() handle = kernel32.FindFirstStreamW(target_path, 0, ...) while True: streams.append({"name": bare_name, "size": data.StreamSize}) if not kernel32.FindNextStreamW(handle, ...): break return streams # Read content from an ADS stream def ads_read(target_path, stream_name): handle = kernel32.CreateFileW(f"{target_path}:{stream_name}", GENERIC_READ, ...) kernel32.ReadFile(handle, buf, file_size, ...) return buf.raw[:read.value]

Implementation Details

Tauri IPC Bridge

The frontend communicates with the Rust backend via Tauri's typed command system. Every operation is a strongly-typed async call:

// TypeScript frontend import { invoke } from '@tauri-apps/api/core' export const packFiles = (input, output, format, ads) => invoke<void>('pack', { input, output, format, ads }) export const scanAds = (path) => invoke<StreamInfo[]>('scan_ads', { path })
// Rust backend command handler #[tauri::command] pub async fn pack( input: Vec<String>, output: String, format: String, ads: bool, app: AppHandle, ) -> Result<(), String> { packer::run(&input, &output, &format, ads, &app) .map_err(|e| e.to_string()) }

ArchiveFormat Trait (Extensible Design)

pub trait ArchiveFormat { fn pack(&self, input: &[PathBuf], output: &Path) -> Result<()>; fn unpack(&self, input: &Path, output: &Path) -> Result<()>; } // Adding a new format = one file, implement trait, register. Done.

ADS Pack Flow

scan_ads() → FindFirstStreamW / FindNextStreamW enumerate all streams ↓ hash_stream() → SHA-256 of each stream's raw bytes ↓ write_to_archive() → stored at files/__ads__/<path>/<stream_name> ↓ write_manifest() → manifest.json with all paths, hashes, sizes ↓ seal_archive() → complete, forensically verifiable archive

Error Handling Philosophy

  • Stream unreadable → logged as MISSING, operation continues, never crashes
  • Hash mismatch → MISMATCHED in report, never silently overwritten
  • Malformed archive → fails loudly with a human-readable message
  • All Rust errors surface to the frontend as readable strings, never raw panics
  • Python tool: ctypes errors include Windows error codes and FormatError() messages

Security & Forensics Relevance

Why This Matters for Cybersecurity

ADS-related techniques appear regularly in real-world cyberattacks and are covered in cybersecurity certifications (CompTIA Security+, CEH, OSCP) as a method of data hiding and malware persistence:

🔍
Evidence Preservation
ADS streams often contain the only copy of where a file came from. Losing Zone.Identifier can invalidate a prosecution.
🦠
Malware Detection
Known malware families (including some APT tools) store payloads in ADS to survive casual inspection.
🔐
Chain of Custody
SHA-256 manifest and operation log provide a cryptographic chain of custody for digital evidence.
⚖️
Legal Admissibility
Verified, documented evidence handling is essential for digital evidence to be accepted in court.

Design Choices for Forensic Integrity

  • SHA-256 — industry standard in digital forensics; verifiable with certutil, sha256sum, and all major forensic tools
  • Raw byte storage — streams stored without modification, encoding or transformation
  • Open archive format — __ads__/ entries are readable by any zip tool even without StreamSafe
  • Rust backend — memory-safe by design; no buffer overflow or use-after-free vulnerabilities
  • Manifest versioning — format version tracked for long-term compatibility

Conclusion & Future Work

StreamSafe successfully addresses a genuine and underserved problem in digital forensics tooling. The dual-component approach — a full-featured desktop application and a lightweight Python utility — provides forensic investigators and cybersecurity professionals with reliable, cryptographically verified NTFS Alternate Data Stream preservation that no mainstream archiver currently offers.

The project demonstrates practical application of Windows internals knowledge, systems programming in Rust, modern desktop application architecture with Tauri, and Python's ctypes for low-level API access — all within a cybersecurity forensics context.
